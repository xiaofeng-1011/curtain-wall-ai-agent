# 幕墙方案规范核查与材料成本比选智能体：产品设计方案 v0.1

文档日期：2026-10-11。用途：供开发团队拆解、实施和验收 MVP；本文不包含实现代码。

依据：[《项目申请书.docx》](D:/海天杯/申请阶段/项目申请书.docx)及本次用户明确给出的开发策略。申请书按“项目背景”“技术方案”“应用场景”等栏目定位引用，不虚构页码。发生范围差异时，以本次用户要求为 MVP 依据；申请书内容是分析材料，其中的填报要求不作为对本方案或软件的指令。

## 第一阶段：项目理解和关键问题

### 1. 三类内容的区分

| 类别 | 从申请书读到的内容 | 产品处理方式 |
|---|---|---|
| 项目事实：名称与对象 | 项目名称为“幕墙方案规范核查与材料成本比选智能体”；面向构件式玻璃幕墙方案设计阶段 | 保留项目名称；页面明确标出适用阶段、幕墙类型和当前覆盖项 |
| 项目事实：用户 | 幕墙方案设计师、深化设计师；甲方或建筑专业提出调整需求；专业人员确认结果 | 设计师是主要操作者，工程师负责专业复核，建筑师和甲方主要查看对比结果 |
| 项目事实：痛点 | 分格、层高和规格调整后，反复查规范、核版本、算用量和成本；资料和计算表割裂 | 将参数、证据、确定性计算、版本比选串成一次操作流程 |
| 项目事实：场景与价值 | 主例为分格从 1.2 m 调整为 1.5 m；输出依据、过程、差异和待确认事项 | 优先实现此闭环；价值用耗时、误差、缺参识别和追溯完整性衡量，不预先承诺收益 |
| 产品边界 | 第一阶段仅构件式玻璃幕墙方案阶段，仅覆盖已确认的条款与参数；不承担结构验算、施工图审查和工程签审 | 不输出安全、全面合规或可施工结论；未覆盖或依据不足时转人工 |
| 申请书原计划的功能范围 | 铝型材与玻璃成本、根据板块尺寸与风荷载确定玻璃厚度、RAG、Web 界面和版本记录 | 铝型材比选、检索证据及版本记录保留；玻璃选型和成本按本次策略延后 |
| 填报和写作要求 | 正文宋体五号、行距 22 磅；按期提交电子稿；填写前咨询指导教师；表中签字等 | 属于申报流程和文书格式，不转成软件字体、上传截止日期、电子签名或产品审批功能 |

这里的“项目事实”指申请书记载的项目情况和拟解决的问题，不表示已独立核验其引用的行业访谈、成本比例或标准效力，也不表示项目功能已经实现。

### 2. 一句话产品定位

面向构件式玻璃幕墙方案设计师，将方案调整转成可确认的参数、带来源的辅助核查和可重算的铝型材理论材料成本对比，帮助工程师复核方案变化影响的设计辅助工具。

### 3. 目标用户与核心问题

| 用户 | 要解决的问题 | 成功时拿到什么 |
|---|---|---|
| 幕墙方案／深化设计师 | 分格改变后要改哪些参数，哪些资料缺失，已覆盖材料用量和成本怎么变 | 一份参数已确认、计算有过程、差异能解释的比选报告 |
| 幕墙工程师／专业复核人员 | 依据是否适用、来源是否可靠、计算口径是否一致、哪里仍须专业判断 | 证据卡片、输入快照、公式与工具版本、待确认事项 |
| 建筑师／项目负责人 | 调整方案的已覆盖成本影响是什么，有哪些尚未解决的条件 | 有范围声明的前后对比，不误认为完整造价或安全结论 |
| 演示和数据维护人员 | 如何稳定演示，如何以后换成企业案例 | 可替换的数据包、验证报告、固定预期结果和离线降级路径 |

### 4. 第一版必须实现与明确不做

**必须实现：**演示数据标识；案例加载和文件替换；自然语言参数提取；关键缺参逐项追问；冲突与单位校验；用户确认参数；规则／规范证据检索；确定性辅助核查；立柱横梁理论长度、质量和材料成本计算；两方案对比；异常阻断或部分结果提示；版本记录；结果导出与追溯。

**明确不做：**CAD/BIM 识别；单元式、石材、金属板幕墙；曲面、洞口、转角及混合或非等距分格计算；玻璃厚度推荐与玻璃成本；风荷载计算、构件承载力与挠度验算、连接与锚固设计；完整工程造价；施工图审查、工程签审、安全鉴定；自动优化选型；完整账号权限体系；全国规范的完整性承诺。

人工复核记录只是辅助软件内的复核留痕，不等同于正式工程签审。

### 5. 事实、假设和待确认事项

| 编号 | 类型 | 内容 | 对本版的处理 |
|---|---|---|---|
| F1 | 申请书事实 | 主场景、用户和设计辅助定位明确 | 直接作为产品需求 |
| F2 | 用户已确定 | 首版允许自构造演示案例，只计立柱与横梁，暂不读 CAD | 优先于申请书原先更宽的材料计算范围 |
| F3 | 用户已确定 | 数值由确定性工具计算；不可靠规范只能作演示规则或待确认资料 | 设置工具调用与证据资格检查，禁止模型补造依据 |
| A1 | 产品假设 | MVP 仅支持单个矩形立面、等距分格、无洞口，宽高可被分格尺寸整除 | 数据导入和计算前显式检查；非整除不自动取整 |
| A2 | 计量假设 | 左右边柱、顶部底部横梁均计入；按轴线理论长度计量 | 输入确认页和报告固定展示，不伪装成下料单 |
| A3 | 演示假设 | 同一规格可用于前后方案的理论数量比较 | 不意味着调整后仍适用，规格适用性始终待工程师确认 |
| A4 | 部署假设 | 首版单人本地浏览器演示；允许用模型处理演示数据 | 推荐 Streamlit；无模型时保留表单和明确标识的本地解析降级 |
| A5 | 比价假设 | 人民币、不含税型材材料单价，价格口径一致 | 不含玻璃、五金、加工、损耗、运输、安装；不等于采购价或工程总价 |
| C1 | 接真实案例前确认 | 企业实际边界计数、横梁净长扣减、接头、损耗和报价口径 | 若与 A1/A2 不符，需要扩展计算模型，不能仅更换数据冒充支持 |
| C2 | 正式规范核查前确认 | 规范来源、合法可用文本、条款效力、适用条件和复核负责人 | 没有可用正式条款时，只运行演示规则 |
| C3 | 企业部署前确认 | 真实资料保密要求、模型部署位置及数据使用权限 | 企业数据默认不外发给外部模型，先确定部署与授权方案 |

目前没有阻止编写本版设计的关键歧义：材料范围已由用户说明解决，几何和计量口径以显式假设固定。C1—C3 是后续接入真实工程的条件。本轮不要求用户一次回答多个问题；后续如改变关键假设，每次只提出一个问题，收到答复再修改相关设计。

### 6. 范围冲突与表述风险

| 申请书表述或潜在风险 | 本版处理 |
|---|---|
| 申请书第一阶段包含玻璃，而当前策略允许只计铝型材 | 将本版命名为“铝型材比选 MVP”；申报或答辩时主动说明玻璃模块未实现，不能宣称原计划全部完成 |
| “根据板块尺寸与风荷载确定玻璃厚度”可能越入安全选型 | 移出本版；后续需独立专业模型和验证，不能交给语言模型判断 |
| “只收录来源确认的规范”与使用演示规则可能混淆 | 演示规则库和正式规范库分开；前者无正式标准编号、条号，不能标注为规范符合性结果 |
| 申请书引用标准更新和条文替代情况 | 只能认定申请书提及该问题；不据此确认任何具体条款在 2026 年仍现行，须逐条核验 |
| “铝材和玻璃各占约 30%”是申请书中的经验陈述 | 不作为计算系数，不从铝型材成本反推玻璃成本或总造价 |
| 分格扩大可能降低立柱用量，但可能要求更换规格等 | 演示结论严格限定为“规格和价格不变、本计量模型下”；不承诺实际工程一定降本 |
| “全部通过”容易被理解成工程合规或安全 | 不设置整方案“安全／全面合规”结论，只展示逐项状态、覆盖数量和人工确认事项 |

## 第二阶段：方案比较与推荐

以下工期是**规划假设**：有一名熟悉相关技术的开发者，可获得产品和工程人员配合，数据使用本文演示包；不含收集和审核正式规范资料的时间。

| 方案 | 开发速度 | 演示效果 | 技术复杂度 | 后续替换数据 | 主要风险 |
|---|---|---|---|---|---|
| Python + Streamlit 本地交互原型 | 约 7—10 个工作日形成 P0 闭环 | 表单、对比表、证据卡和导出易实现；视觉与多用户能力有限 | 低至中；同一语言连接计算、校验、检索和界面 | 低；数据按统一文件结构加载，业务模块不写死案例 | 页面重运行导致状态丢失；UI 与逻辑耦合；模型网络不稳定 |
| 前后端分离 Web 应用 | 约 15—25 个工作日，人员熟练度影响较大 | 交互自由，便于多用户、权限和部署 | 中至高；需维护前后端、接口、存储和部署 | 低至中；有稳定数据契约时容易迁移 | 首版容易把精力耗在工程框架；前后端计算或字段定义不一致 |
| 低代码智能体平台 | 约 3—5 日搭对话演示；完整追溯闭环约 7—12 日且受平台能力限制 | 对话展示快；复杂参数编辑、对比和审计通常受限 | 初期低，接独立计算服务后为中 | 中；知识库、文件格式、工作流和插件可能与平台绑定 | 让模型直接计算、引用不可靠、导出和版本能力不足、数据外发和平台费用 |

**推荐：Python + Streamlit，本地运行，计算与数据模块独立。**本版最需要验证的是真实可操作的业务闭环、确定性计算和证据追溯，这个方案的实现成本与目标匹配。Streamlit 也是浏览器中的 Web 界面，不与申请书的 Web 交互方向矛盾。

产品划分为交互界面、流程控制、参数校验、检索与规则执行、确定性计算、版本与报告六个模块。界面只展示和收集数据；计算模块不依赖界面；案例、规格、价格和证据均来自数据包。后续有多人使用和企业部署需求时，迁移界面与服务层，保留数据契约及计算模型。

本版不强制引入向量数据库。小规模知识库先采用元数据过滤与关键词检索，再将检索到的证据交给模型解释，形成受约束的 RAG；向量检索列为 P1。

## 第三阶段：完整产品设计

### 1. 产品概述与目标

**产品交付物：**一个可交互的本地应用、一套明确标记的演示数据包、一组人工可复算的预期结果，以及可以导出的比选报告。

**MVP 目标：**用户从“分格由 1.2 m 改成 1.5 m”出发，在一次现场流程中完成参数确认、缺参追问、辅助核查、数量与成本计算、前后比较和版本追溯。没有正式条款时，应准确演示规则流程及其限制。

**主成功指标：**主案例计算正确；关键缺参不漏拦；每项结果找到输入和计算依据；每条规则显示真实来源状态；用户修改参数不会覆盖已保存版本。效率改善幅度在真实用户测试后测量，不预设百分比。

### 2. 用户角色与典型使用场景

| 场景 | 操作者 | 触发和操作 | 预期结果 |
|---|---|---|---|
| 分格调整 | 设计师 | 选基准方案，输入“分格从 1.2 m 改为 1.5 m” | 候选方案只更改分格宽度，继承项可见，确认后计算 |
| 缺参补全 | 设计师 | 某一关键参数为空或显式清空 | 系统一次追问一项，解释用途；未补全的模块不能运行 |
| 核查复核 | 工程师 | 查看规则命中、原文和来源状态 | 分清演示规则、正式依据、待确认事项和未覆盖问题 |
| 规格敏感性比较 | 设计师 | 手动将候选方案改用另一组型材 | 成本按所选规格重算，系统不宣称该规格满足承载要求 |
| 替换企业案例 | 数据维护人员 | 导入同结构、符合计算覆盖范围的数据包 | 先校验并预览，不覆盖历史记录；合格后启用 |

角色是职责划分。P0 不建设登录系统，复核人信息仅作记录；不能把该记录视为身份认证或法律意义的签审。

### 3. MVP 范围与优先级

| 优先级 | 含义 | 内容 |
|---|---|---|
| P0 | 任一缺失即不能交付主演示 | 单矩形等距立面；两方案；四个演示型材规格；单位校验；缺参追问；来源标识；规则证据；确定性数量和成本；版本；文件替换；报告导出；异常及离线降级 |
| P1 | 不阻塞主闭环，P0 验收后实施 | 向量检索；专业复核记录；三个及以上方案比较；便利的批量数据维护 |
| P2 | 独立立项或评估后实施 | CAD/BIM、其他幕墙类型、企业多人部署、玻璃材料模块、复杂立面和更精确采购计量 |

P2 不表示已经承诺交付。完整结构计算、正式签审不纳入本产品当前路线；如未来需要，应作为专业系统另行定义责任和验证要求。

### 4. 用户完整操作流程

1. 打开应用，看到“演示数据／仅供方案辅助”以及本版覆盖项。
2. 加载演示案例或导入数据包；系统展示来源、版本和校验结果。
3. 选择调整前方案作为基准，输入调整需求。
4. 模型提取变更草案；界面分别列出“本次修改”“继承基准”“缺失／冲突”，用户可以编辑。
5. 程序检查适用范围、单位、可比性，以及当前运行入口所需的字段；存在缺项时一次追问一项。
6. 系统先生成基础几何快照，再按用户选择的运行入口确认对应模块的字段；显式清空的字段不得用基准值偷偷回填。
7. 系统先确定当前案例的必查规则清单并逐项执行；关键词检索只用于补充证据，不能代替必查规则。规则程序执行机器可判定的条件，无法判定的条款标记待人工判断。
8. 计算工具按模块依赖分别计算几何、长度、质量和成本，差异工具只比较满足同口径条件的结果。
9. 页面展示已完成的数量、成本、逐项核查、证据、计算过程与人工确认事项；缺乏正式规范时突出“未完成正式规范核查”，缺少某模块字段时展示可用的部分结果和阻断原因。
10. 保存结果版本，导出比选包；再次修改生成新草稿和新版本，旧版本保持不变。

用户可以只做规范查询、基础几何／长度计算、单方案质量计算或两方案成本比选；每个入口只要求自身必要字段，报告依然使用同样的来源和范围规则。

**运行入口与字段门槛：**

| 运行入口 | 最少必要字段 | 可输出结果 | 缺字段时的行为 |
|---|---|---|---|
| 规范查询／辅助核查 | 幕墙类型、设计阶段、当前案例必查规则所需的参数；如规则需要几何，则先完成几何快照 | 逐项核查状态、证据和待确认项 | 只追问该规则缺少的字段，不要求无关的型材或价格字段 |
| 基础几何／长度 | W、H、b、h、计量模型；W/b 与 H/h 必须为正整数 | 面积、格数、立柱／横梁道数及理论长度 | 阻断长度及依赖模块；不阻断单纯规范查询（除非规则需要几何） |
| 单方案质量 | 基础几何／长度字段，加上立柱和横梁线重及有效规格引用 | 分项和总质量、单位面积质量 | 允许保留几何／长度结果；质量模块显示缺少的线重 |
| 两方案成本比选 | 两个方案各自满足几何和质量字段，加上两套型材价格、统一价格口径和可比性字段 | 分项／合计金额、单位面积成本、差值和变化率 | 允许查看已完成的几何、长度或质量；阻断完整成本比较 |

基础几何是 R02 等板块面积规则的前置步骤。系统不得因为成本字段未填而跳过可执行的几何和核查结果，也不得把部分结果包装成完整比选。

### 5. 智能体状态流程

| 状态 | 进入条件 | 允许操作／退出条件 |
|---|---|---|
| 未开始 | 尚未选择案例 | 加载案例或导入数据包 |
| 识别任务 | 输入自然语言或表单变更 | 识别查询、单方案、两方案比选；先检查覆盖范围 |
| 范围外 | 类型或任务不受支持 | 说明未覆盖；仅经用户确认将任务缩小到支持范围后继续 |
| 等待补参／消冲突 | 当前运行入口所需字段缺失、单位不明、输入互相矛盾 | 一次问一项；已确认字段保留；阻断受影响模块，但允许展示已满足门槛的部分结果 |
| 等待参数确认 | 当前运行入口字段完整且基础校验通过 | 展示继承值和假设；用户确认后冻结本次输入快照 |
| 检索与核查 | 快照已确认 | 检索证据并执行可判定规则；证据不足只影响核查模块 |
| 计算与比较 | 所选模块所需字段完备 | 按依赖顺序调用确定性工具；失败不得由模型补算 |
| 部分完成 | 某模块可完成，其他模块缺依据或缺参数 | 展示已完成部分及明确缺口；不得包装成任务全部成功 |
| 完成／待专业确认 | 已生成可展示的结果 | 保存、导出、查看追溯；“完成”指流程完成，不代表工程批准 |
| 执行失败 | 工具超时、校验异常、文件损坏 | 保留草稿和错误原因；允许重试，不修改旧成功结果 |

任意参数、规格、价格、规则版本发生变化，当前结果立即标记“已过期”，必须重新确认、检索和计算。模型输出不直接控制“完成”状态，由程序根据模块执行结果决定。

### 7. 规范检索模块设计

#### 7.1 两类证据，分别展示

| 证据集合 | 可收录内容 | 使用条件 | 呈现方式 |
|---|---|---|---|
| 演示规则库 | 团队编写的流程验证规则 | source_status=synthetic；显式记录阈值仅作演示 | “演示规则 DEMO-Rxx”，不得填写虚假标准名或条号 |
| 正式规范／企业规则库 | 有原始来源、版本和适用范围的条款 | 来源可查，条款级效力与适用性经审核；当前任务满足所需条件 | 原文与解释分区，显示准确出处和审核状态 |

公开资料的 public 状态不自动等于“现行、适用、允许作结论”。verified 也不自动等于“当前项目适用”。企业规则必须标明企业规则类型，不冒充国家或行业标准。

#### 7.2 条款记录结构

| 字段组 | 必须记录的字段 | 约束 |
|---|---|---|
| 身份 | evidence_id、evidence_type、standard_name、standard_number、edition、clause_number | 演示规则的正式标准字段为空，不生成仿真标准编号 |
| 文本与出处 | exact_text、source_ref、page_or_location、content_hash | 原文必须来自可核验来源；摘要不得写进“原文”字段 |
| 时间与效力 | publication_date、effective_from、effective_to、effect_status、replaced_by、status_checked_at | 支持现行、废止、被替代、部分替代、未知；关联到具体条款，不只记录整本标准 |
| 适用条件 | curtain_wall_type、design_stage、region、required_parameters、applicability_notes | 不明确的关键适用条件不能由模型自行补全 |
| 规则化 | machine_checkable、predicate、thresholds、required_tools、rule_version | 仅执行受控操作符和计算工具，不执行数据文件中的任意代码 |
| 来源与审核 | source_status、source_type、review_status、generation_method、reviewer、reviewed_at、review_scope | 来源身份、人工审核、生成方式和规则映射分别记录；未审核内容不用于正式判断 |

#### 7.3 检索与核查流程

先用幕墙类型、阶段、地区及项目核查日期过滤，并为当前案例确定版本化的“必查规则清单”；清单中的每一项都必须执行并记录状态，即使该项对应的参数没有发生变化。关键词检索用于补充证据和发现可能遗漏项，不能代替必查清单，也不能因为某项没有被关键词召回就视为通过。逐项检查来源、条款效力、替代关系和适用条件，只将有资格的证据交给模型解释，所有规则命中与差异数值由程序产生。

输出状态及触发条件如下：

| 状态 | 触发条件 | 解释边界 |
|---|---|---|
| 演示条件满足 | synthetic 演示规则的条件为真 | 只表示演示条件成立 |
| 演示关注项触发 | synthetic 演示规则的条件为假 | 只表示演示关注，不能称为违反规范 |
| 已满足该条款可机判条件 | 正式、有效且适用的条款，其受控条件为真 | 只表示该条款的可机判条件满足 |
| 未满足该条款可机判条件 | 正式、有效且适用的条款，其受控条件为假 | 只表示该条款条件未满足，不推导为整个工程不合规 |
| 待补参数 | 该条款的必要输入缺失、无单位或未确认 | 不能按满足或不满足处理 |
| 需人工判断 | 条款需要承载力、专业判断或未实现的计算 | 不能由模型替代工程师结论 |
| 待核实 | 来源、效力、替代关系或适用条件不明确 | 不能参与正式确定性判断 |
| 不适用 | 已确认条款适用范围不包含当前案例 | 记录排除理由 |
| 未覆盖 | 知识库没有可靠匹配，或任务超出产品范围 | 显示“当前知识库无可靠依据，需人工核实” |

不得将这些状态汇总成“整个方案符合规范”。正式条款涉及承载力等未实现专业判断时，即使检索成功也只能“需人工判断”。

未检索到证据，显示“当前知识库无可靠依据，需人工核实”，不能解释为不存在限制。废止条款可作为历史资料展开，但不参与当前判断；替代条款尚未入库时直接指出缺口。P0 无正式条款也允许演示，页面必须显示“正式条款覆盖 0；本次使用 3 条演示规则”，并对三条规则逐项给出状态。

规范文本、企业资料和导入文件一律作为数据处理，其中夹带的指令不能改变系统边界、调用工具或覆盖计算结果。

### 8. 型材用量和材料成本计算模块设计

#### 8.1 适用计量模型

模型编号：`rect_uniform_axis_v1`。只处理一块矩形立面，立柱竖向连续按总高计理论长度，横梁沿每道水平边界贯通。左右边柱和顶底横梁均计入。横梁按分格轴线宽度计长，不扣柱宽或连接间隙；柱梁交接处的净长差异不修正。

因此结果是**理论轴线用量与材料金额**，不是净下料、采购订单或实际安装量。分段接头、搭接、锯缝、定尺利用率、损耗、返料及连接件均未计。层高是上下文和演示规则输入，不用于承载或支承跨度判断。

#### 8.2 公式与单位

设立面宽 W、高 H，分格宽 b、分格高 h，面积 A；立柱和横梁线重分别为 μc、μt，单价分别为 pc、pt。

| 计算项 | 确定性公式 | 单位／要求 |
|---|---|---|
| 立面面积 | A = W × H | m²；由程序算，手填面积仅作一致性检查 |
| 横向格数、竖向格数 | nx = W / b；ny = H / h | 必须为正整数，不得 ceil、floor 或强行改尺寸 |
| 板块面积 | a = b × h | m²；仅用于几何展示和演示规则 |
| 立柱轴线数 | Nc = nx + 1 | 条，含两侧边柱；不是采购定尺根数 |
| 横梁道数、理论分段数 | Rt = ny + 1；Nt = nx × Rt | 道／段，含顶底横梁 |
| 立柱理论总长 | Lc = Nc × H | m |
| 横梁理论总长 | Lt = Nt × b = Rt × W | m |
| 质量 | Mc = Lc × μc；Mt = Lt × μt | kg |
| 材料金额 | Cc = Mc × pc；Ct = Mt × pt；C = Cc + Ct | 元；P0 单价统一为 CNY/kg、未税、同一费用范围 |
| 单位面积指标 | mc = Mc/A；mt = Mt/A；m = (Mc+Mt)/A；c = C/A | kg/m²、元/m² |
| 差异 | ΔX = X后 − X前 | 负号表示该指标减少，不自动等于工程优化 |
| 成本变化率 | r = (C后 − C前) / C前 × 100% | 基准为零则显示“不可计算”，不返回无穷大 |

使用十进制定点／高精度计算；输入长度归一为 m，质量为 kg。中间值不因显示而截断。质量和长度显示 3 位小数，金额显示 2 位，单位面积质量显示 4 位，百分比显示 2 位；采用明确的四舍五入规则。合计和差值都从未舍入结果计算。

#### 8.3 可比性与缺参策略

- 主比选要求相同立面宽高、面积、计量模型、边界计数、货币、税口径和包含费用。输入不同则阻断“分格调整造成的节省”结论，提示口径差异；单方案结果仍可查看。
- 规格或价格变化允许比较，但必须列明变更，不能把全部差异解释为分格效应。P0 不做多因素自动归因分摊。
- 各运行入口的字段门槛见第 4 节的“运行入口与字段门槛”表。几何缺失时不计算长度；线重缺失时可给长度，不给质量；价格缺失时可给质量，不给完整成本。完整比选按钮保持阻断，部分结果逐项标记。
- 只有核查依据缺失而计算参数齐全时，数量和成本可以完成，核查模块独立标记“待核实”。
- 程序不能由规格名称猜线重，也不能由型材重量推断承载性能。价格按价目表 ID 和版本匹配，不以“最新”自动替代历史价格。

执行顺序固定为：**基础几何 → 必要的规则核查 → 理论长度 → 质量 → 成本与比选**。规范查询可以在几何完成后独立运行；不需要成本字段。若某一步缺少本步字段，系统保留前一步结果并进入“部分完成”，禁止用缺失数据估算后续结果。

规则清单中的每一项都必须运行。比如只修改分格宽度时，层高未变，仍须执行 DEMO-R03；板块面积规则 DEMO-R02 必须等待基础几何完成后再执行。单项规则缺参只阻断该项，不阻断不依赖该项的长度或成本结果。

### 9. 演示案例数据结构与预期结果

#### 9.1 来源状态与可替换数据包

| source_status | 含义 | 产品要求 |
|---|---|---|
| synthetic | 团队构造的演示数据来源 | 全程显示“演示数据”；人工检查算术不会改变其演示身份 |
| public | 可定位的公开资料来源 | 保存原始链接／文件、定位和获取时间；不自动代表适用或现行 |
| verified | 企业或专业人员已确认的数据来源 | 保存确认人、时间、范围及依据；只对已确认字段生效 |
| pending | 来源身份、来源内容或来源可用性待确认 | 列明待确认原因；关键输入不得用于正式确定性结论 |

`source_status`只描述来源状态，不描述审核是否完成。每个外部输入数值、规则和引用均关联 provenance，不能仅给整个文件一个标签。另行记录：`source_type`（team_constructed、public_document、enterprise_record、unknown）、`review_status`（unreviewed、in_review、pending_professional_review、technically_reviewed、rejected、outdated）、`generation_method`（provided、program_derived、llm_extracted、engineer_adjusted）、`source_ref`、`reviewer`、`reviewed_at`、`notes`。缺少来源状态的导入项归入 pending 并显示提示。

用户确认“此值用于本次演示”与确认真实工程数据是两件事。模型提取值在用户确认前 `generation_method=llm_extracted` 且 `review_status=unreviewed`，不能给模型直接填写 verified 的权限。派生结果记录全部 input_refs、输入来源状态、生成方式和计算版本；本演示的派生结果为 `source_status=synthetic`、`generation_method=program_derived`。真实案例的派生结果按输入来源聚合 source_status：任一关键输入为 pending 则结果为 pending；输入来源确定时保留其来源等级，但不因此表示结果已被人工审核；结果另外标记 `review_status=pending_professional_review`。混合来源必须逐项显示，不能用单一绿色标签掩盖 synthetic、public、verified 或 pending 项。

| 文件／对象 | 主要内容 | 关键约束 |
|---|---|---|
| manifest.json | schema_version、dataset_id、dataset_version、各文件清单与哈希、默认案例 | 导入先校验；P0 支持单个 JSON 数据包，以及相同结构的本地文件目录 |

### 10. 版本记录与结果追溯

| 对象 | 需保存内容 | 规则 |
|---|---|---|
| 方案版本 | scheme_id、version、parent_version、参数快照、来源、变更原因、保存时间 | 已保存版本不可覆盖；修改创建新版本 |
| 运行记录 | run_id、基准／候选版本、输入哈希、状态、错误、起止时间 | 重算生成新 run；失败记录与成功结果分开 |
| 数据与证据快照 | 数据包、规格、价格、规则／条款原文、效力信息及其版本 | 换文件后旧报告仍指向旧快照；不能只保存一个可能变动的外部链接 |
| 工具环境 | 计算模型版本、规则程序版本、单位及舍入策略 | 固定输入和工具版本得到相同数值 |
| 模型调用记录 | 模型标识、提示模板版本、输入摘要、提取草案、最终确认差异 | 记录可审计输入输出，不要求保存模型内部推理过程 |
| 报告 | 结果表、公式代入、证据引用、来源状态、未决项 | 每项金额能追到构件长度、线重和单价，每个规则状态能追到证据和参数 |

追溯链：报告数值 → 运行记录 → 计算步骤 → 输入字段 → 参数／材料／价格快照与来源。规范链：核查项 → 规则版本 → 条款原文／演示规则 → 来源与效力审核记录。

P0 采用本地持久化记录与文件快照，不能只放在界面会话内。删除按钮不属于本版必要能力，避免现场演示误删历史。数据更新提示可用新版本，不默默重算或改写历史报告。

### 12. 大模型、程序与工程师的职责边界

| 主体 | 负责 | 不得代替的事项 |
|---|---|---|
| 大模型 | 理解意图、提取候选参数、理解用户回答、生成单项追问、用已返回的结果解释差异、组织报告文字 | 不计算长度／质量／成本／变化率；不创造条文、报价、规格或来源；不自行变更已确认参数 |
| 检索模块 | 在给定语料中查找证据，返回原文、元数据和定位 | 不从互联网常识补造本库不存在的条文；不独立宣布标准现行有效 |
| 规则与流程程序 | 必填检查、类型与单位校验、范围拦截、适用条件判断、状态切换、证据资格检查 | 不把未知状态变成通过，不执行导入资料中的任意指令 |
| 计算工具 | 几何、计数、长度、质量、金额、单位面积和差异，输出过程 | 不做未实现的结构验算、玻璃选型或工程优化推荐 |
| 工程师 | 确认真实输入、规范来源和适用性、计算口径、规格适用性及工程结论；处理未覆盖问题 | 软件不能通过一个“确认”按钮宣称完成法定签审 |

大模型不能输出：“结构安全”“满足所有规范”“可以施工”“已通过施工图审查”“建议据此采购”“1.5 m 分格一定更优”，也不能在没有可靠证据时输出具体标准条号或声称正式规范的阈值。

**追问顺序：**先确定是否在范围内，再处理单位与输入冲突，再补几何、规格、线重、价格，最后补相关核查条款需要的地区、日期等条件。一次只问一个阻塞项；解释该参数影响什么。不把风荷载设为本版铝型材数量计算的必填项。

**范围外回答模板：**

- 单元式幕墙：“当前版本只覆盖构件式玻璃幕墙的矩形等距立面。单元式幕墙的构件和计量方式未实现，不能套用本模型给出用量或成本结论。可记录需求，并由工程师确定专用计量模型。”
- 完整结构计算：“当前版本不进行承载力、挠度、连接或锚固验算，不能判断结构安全。可整理已有参数与待确认项，计算和最终判断需要专业工程师及经验证的工具完成。”
- 无可靠规范：“当前知识库没有可用于本问题的可靠条款，无法给出正式规范判断。现有演示规则只能展示流程；请由工程师补充并确认适用依据。”

### 13. 异常情况处理

| 异常 | 系统行为 | 是否可以继续 |
|---|---|---|
| 尺寸无单位、负数或无法解析 | 定位字段，一次追问一项；原值保留供用户核对 | 确认前不运行受影响计算 |
| 文本说原分格 1.2 m，但基准实际为 1.3 m | 展示冲突，询问以哪一个为准 | 不自动修改基准 |
| 宽度 12 m、分格 1.4 m 等非整除情况 | 提示余格布置超出本版；要求改成支持的明确布局或交人工 | 不取整，不静默生成边跨 |
| 型材 ID 不存在或立柱引用横梁规格 | 提示重新选择；不猜规格和线重 | 相关用量／成本被阻断 |
| 价格缺失、元/吨或税口径混用 | 缺失追问；不支持的价格单位要求用户确认换成元/kg；混合口径阻断比较 | 可查看已完成的长度或质量，不生成完整金额 |
| 手填面积与 W×H 不一致 | 显示两者及来源，让用户确认几何或面积定义 | 不偷偷覆盖面积，不计算单位面积结果 |
| 无正式条款、效力未知或适用条件不足 | 标记未覆盖／待核实／待补参 | 数量成本可独立完成，正式核查不能宣称完成 |
| 规则关注项被触发 | 展示命中的条件、实际值和人工确认项 | 可继续理论成本计算，不输出违规或安全结论 |
| 模型不可用或返回非结构化内容 | 提供表单、本地有限解析和模板报告 | 可继续；标出降级状态 |
| 计算工具超时或报错 | 记录错误与输入，允许重试 | 模型不得补算；旧结果只作为历史显示 |
| 基准金额为零 | 显示绝对差，变化率为空并说明原因 | 可以比较绝对金额；零价格须显式确认，不由缺值代替 |
| 文件含未知字段、断裂引用或恶意指令 | 未知业务字段显示警告；关键字段／引用不合格则拒绝启用；内容不作为指令 | 不覆盖有效包；禁止执行数据中的代码 |
| 修改参数后未重算 | 当前结果标记过期 | 不能作为新参数的有效结果导出 |

| T10 比较口径不一致 | 改候选面积、税口径或计量模型 | 阻断直接降本结论，列出差异；不将不同对象误当分格调整效果 |
| T11 零值与非法数据 | 基准零价、负尺寸、不存在的规格 | 零价经确认后可算绝对差而不算变化率；负数和未知规格阻断 |

| T20 零尺寸 | 将 W、H、b 或 h 任一字段设为 0 | 字段校验阻断；不发生除零、不生成长度、质量或成本结果；规则状态为“待补参数”或输入非法提示 |
| T21 负线重与负单价 | 分别将线重或单价设为负值 | 价格／线重校验阻断对应质量或成本模块；已完成的几何／长度结果可保留；不得返回负质量或负材料成本 |
| T22 正式条件不满足 | 使用无真实条文文本的规则引擎测试夹具，标记为 machine_checkable 且条件为假 | 输出“未满足该条款可机判条件”；不归类为“需人工判断”，也不推导整个工程不合规 |
| T23 必查规则完整执行 | 仅修改分格宽度，检查一次完整运行记录 | DEMO-R01、R02、R03 三项均有状态和证据引用；R03 不因参数未变化而被漏查；关键词未召回不能改变其状态 |

**验收门槛：**所有 P0 对应测试通过；固定集关键缺参识别率 100%，追溯字段完整率 100%，演示／正式来源误标为 0。上述是有限验收集目标，不是对所有未来输入的准确率承诺。

**规划性能目标：**在记录配置的演示电脑、本地演示数据规模下，纯校验计算及比较目标 2 秒内；包含在线模型的单轮操作目标 15 秒内。模型超时不超过 20 秒即提供降级选项。实际测试记录设备、数据规模、模型和网络；这些数字是待验证的产品目标。

### 17. 风险、限制和后续扩展

| 风险／限制 | 本版控制 | 后续条件 |
|---|---|---|
| 演示通过但工程有效性未知 | 明确 synthetic，所有规则阈值不声称工程依据 | 接入经过授权与审核的企业案例，与工程师现有工作表做对照 |
| 理论轴线长度与采购量有差距 | 报告列明边界计数、净长未扣和损耗未计 | 单独扩展净长扣减、节点、定尺、损耗模型并验证 |
| 规范版本与替代关系维护成本 | 条款级效力、来源、审核记录和范围过滤 | 指定专业维护负责人；定期核验，不自动宣布新旧替代 |
| 模型遗漏参数或编造解释 | 程序确定必填项；数值和引用绑定工具；输入确认 | 扩充脱敏语句测试集，记录提取后用户修改量 |
| 相同规格调整后可能不适用 | 永不把成本低等同于安全或推荐采用 | 专业人员确认规格；如接外部验算工具需独立明确责任边界 |
| 企业数据结构与演示不同 | 声明只支持同契约和已覆盖模型的文件替换 | 数据映射、合法使用及模型部署确认后再接入 |
| Streamlit 的并发和权限限制 | 本地单人优先，状态与业务模块分离 | 真实多人需求出现后迁移服务架构与权限体系 |
| 首版省略玻璃导致成本理解偏差 | 标题和合计统一为“已覆盖铝型材理论材料成本” | 可先增加“工程师给定玻璃配置”的数量成本，不自动推荐玻璃厚度 |

后续建议依次验证：真实案例和计算口径 → 经审核的正式规范检索 → 更精确的型材计量 → 工程师给定配置的玻璃材料成本 → 多方案和多人协作 → 经单独设计验证的其他幕墙类型。每次扩展都需要更新覆盖清单、数据契约和验收案例，不能仅修改页面文案宣称支持。
