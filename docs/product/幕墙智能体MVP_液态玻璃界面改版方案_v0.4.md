# 幕墙方案助手：液态玻璃界面改版方案 v0.4

日期：2026-10-12  
状态：设计提案，尚未实施。适用于当前 v0.3 MVP。  
目标：保留聊天式工作方式，修正名称、布局和操作反馈问题，建立统一的液态玻璃视觉与交互系统。

## 1. 结论与设计边界

推荐采用「浅色冷灰底、蓝色强调、玻璃化操作层、清晰内容层」的专业工具界面。首先修复对话名称、顶部裁切、侧栏对齐和当前状态识别，再引入玻璃材质。不能把整页透明、增加模糊或换圆角作为完成标准。

继续保留：空白启动、单一聊天入口、原方案与调整方案、按需补参、确定性计算、输入与结果追溯。设计不扩大工程计算能力，不新增预装案例、不把资料检索包装成正式规范核查。

本方案主要服务中文桌面浏览器，基准视口为 1440×900，同时覆盖 1366×768、平板和窄屏。默认浅色；深色模式作为后续完整主题，不作为本轮交付依赖。

### 1.2 风格选择

| 方向 | 特点 | 适配判断 |
|---|---|---|
| **A. 浅色专业液态玻璃，推荐** | 冷灰背景、轻微透色、清楚的边缘高光，内容近白底 | 长时间读中文、比较数字、进行现场演示较均衡 |
| B. 深色液态玻璃 | 深蓝灰背景、高光更明显 | 展示感较强，但表格、来源警告、附件预览需要独立适配 |
| C. 高透明流体玻璃 | 更强的折射、流动和背景变形 | 可用于品牌展示；持续聊天与工程数据阅读容易分心，性能成本也更高 |

选择 A。液态感由材质分层、边缘高光、轻微透色和短促反馈共同形成，不依赖持续流动的背景动画。网页实现是对液态玻璃语言的近似，不承诺复现 Apple 原生渲染。

## 3. 页面结构与布局

### 3.1 桌面布局

```text
应用背景：浅冷灰，低对比度蓝灰光晕
┌──────────────────┐  ┌────────────────────────────────────────┐
│ 标识  幕墙方案助手 收起 │  │ 对话标题                         ⋯     │
│ ＋ 新对话           │  │ 所属项目 · 当前编辑方案 · 状态    方案参数 │
│ 搜索对话           │  ├────────────────────────────────────────┤
│                    │  │                                        │
│ 最近对话           │  │              用户问题 / 附件            │
│  对话名称       ⋯  │  │  助手答复                               │
│  当前对话名称   ⋯  │  │  结果卡 / 导入预览 / 参数确认            │
│  对话名称       ⋯  │  │                                        │
│  ……历史区独立滚动  │  │                                        │
│                    │  │        有新结果 ↓（有需要时出现）         │
│ 项目               │  │ ┌────────────────────────────────────┐ │
│ ───────────────── │  │ │ 待发送附件                          │ │
│ 资料库   材料库    │  │ │ 输入尺寸、材料或你的问题…             │ │
│ 设置              │  │ │ 附件  空白模板                  发送 │ │
└──────────────────┘  │ └────────────────────────────────────┘ │
                      └────────────────────────────────────────┘
```

这是区域关系示意，不是已实现截图。资料库、材料库打开独立管理视图；左侧“项目”打开项目列表，已有关联会话进入最近会话，无会话项目可开始新对话。P1 不新增复杂多级项目树。

### 3.2 尺寸基准

| 元素 | 桌面规格 | 约束 |
|---|---|---|
| 应用外边距 | 16px | 窄屏降至 8–12px |
| 侧栏 | 默认 264px；允许范围 248–288px | 不能按对话标题长度撑宽 |
| 侧栏与主区间距 | 16px | 降低无用途分割线数量 |
| 顶部标题区 | 最小 76px；单行标题与一行辅助信息 | 内容增大时允许增高，禁止固定高度裁字 |
| 聊天阅读区 | 最大 820px，居中 | 正文建议约 36–46 个全角字符／行，实际随字号变化 |
| 结果表格 | 随聊天区，详情可到 960px | 小屏在表格自身横滚，不撑出页面 |
| 输入区 | 与聊天区同宽；底部间距 16px | 留出内容底部安全区，不遮最后一条消息 |
| 参数详情 | 宽屏可用 400–440px 侧面板 | 不够宽时使用模态详情，避免挤压正文 |

顶栏与输入栏共用主内容的左右基线。顶部标题不与头像左缘、气泡左缘、表格内边距混为同一基线。

### 3.3 响应式规则

- ≥1280px：默认展开侧栏；只有同时容纳侧栏、详情和至少 640px 聊天区时才并排显示参数面板，通常从 1440px 起适用。空间不足时使用模态详情。
- 960–1279px：侧栏默认收起至 64px 工具栏；历史通过展开面板查看；参数使用模态详情。
- <960px：侧栏改抽屉，菜单按钮位于顶栏左侧；主区占满可用宽度。
- ≤600px：保留单行可省略标题；项目和方案信息改为可展开摘要；不同时显示多个文字工具按钮；参数使用全屏详情。
- 200% 浏览器缩放时按可用 CSS 视口重新排版，标题可换行、操作可收起；不能只缩小字体。
- 开启虚拟键盘时输入区跟随可见视口，长输入在自身范围内滚动。

## 4. 侧栏与图标专项修改

### 4.1 对话行结构

每行视为一个完整组件，而不是两个彼此独立的列。行高 44px，内边距左右 10–12px，圆角 10px，垂直居中。结构为：可选 18px 对话图标、8px 间距、弹性标题、8px 间距、固定 32px 更多按钮。

- 标题区域允许收缩，单行显示，超出使用视觉省略；不提前把原始标题截成 18 字。
- 更多按钮使用三点图标本体，视觉尺寸 18–20px；桌面点击区域 32×32px，触屏提高至至少 44×44px。
- 更多按钮低对比度常显，悬停和键盘聚焦增强。所有行预留相同空间，不能悬停时挤动标题。
- 标题区打开会话，更多按钮只打开菜单；两个操作是相邻控件，不能把按钮嵌套在另一个按钮里。
- 全名通过悬停、键盘聚焦提示可见；窄屏可通过对话详情或重命名表单查看，不能只依赖悬停。
- 当前项使用淡蓝填充、较深文字与窄侧标识；焦点框与选中态独立。选中不是仅换一个几乎看不出的灰色。
- 长短标题、纯中文、英文混排、带数字、图标缺省时，更多按钮横坐标一致。

### 4.2 图标体系

沿用当前 Material Symbols 方向，统一使用线性图标、相同字重和 20px 默认尺寸，避免为换风格再引入第二套图标库。

| 功能 | 图标语义 | 放置规则 |
|---|---|---|
| 新对话 | 加号或新建对话 | 文字左侧 8px；唯一较突出侧栏按钮 |
| 收起／展开 | 侧面板开合 | 侧栏品牌行右端；收起后在工具栏顶部 |
| 搜索 | 放大镜 | 搜索框内左侧；不是另一个无标签功能 |
| 更多 | 水平三点 | 所有历史行固定右侧 |
| 资料库 | 文档集合 | 底部工具区，配文字 |
| 材料库 | 材料／库存 | 底部工具区，配文字 |
| 设置 | 齿轮 | 底部固定区 |
| 附件 | 回形针 | 输入框工具行左侧 |
| 发送 | 向上箭头 | 输入框工具行右侧；禁用、可用、处理中区分 |

图标与文字先采用布局居中，再按实际图形做至多约 1px 的光学校正；不能靠全角空格、换行、不同字符大小“调齐”。每个纯图标按钮必须有可读名称、提示及键盘焦点。

### 4.3 历史与管理

历史按“今天／近 7 天／更早”分组，空组不显示；超过首批记录提供“加载更多”。搜索标题时检索全部未删除会话，不只是屏幕上已加载的 40 条。搜索为空显示“没有找到对应对话”和清除搜索动作。

对话菜单仅保留“重命名对话”“移入回收站”。项目删除进入明确的项目管理入口，显示项目名与关联影响，避免从某条聊天的菜单误删整个项目。

## 5. 对话名称与顶部裁切专项修改

### 5.1 名称职责

| 对象 | 含义 | 显示位置 |
|---|---|---|
| 对话标题 | 当前聊天的主题 | 顶栏主标题、侧栏、浏览器页面标题 |
| 项目名称 | 工程或计算数据的归属 | 顶栏第二行“项目：……”、项目详情、导出资料 |
| 当前编辑方案 | 下一次参数修改的对象 | 第二行“原方案／调整方案”明确标识 |

无项目的问答依然有完整的对话标题，不创建占位工程项目。项目名和对话标题允许相同，但这是内容上的巧合，不代表两者自动绑定。

### 5.2 命名规则

1. 尚未提交消息时显示“新对话”；点击新对话不创建无意义历史记录。
2. 第一条有效消息提交成功并保存后，立即给会话设置可读标题，不等待在线模型完成，也不等待计算项目建立。
3. 默认提取首条消息的简短主题；先使用确定性的文本清理与截取，自动标题目标 12–20 个汉字、最多 28 个字符。不依赖额外一次模型请求。
4. 对普通问答，保留用户关键词。例如截图中的消息可命名为“玻璃幕墙立柱截面厚度要求”。不根据失败答复改成“结构安全限制”。
5. 附件-only：优先用清理后的文件名形成“文件主题 · 导入／查阅”；多文件用第一个文件主题加“等文件”。大段表格可用“方案表格导入”。生成后可手动修改。
6. 自动标题首次生成后默认稳定，不随每轮对话、项目建立或模型返回而跳变。
7. 手动名称支持最多 40 个用户可感知字符；超限在输入时提示，不静默截断。前后空白移除；拒绝纯空白。
8. 建议记录名称来源 `default / auto / manual`。用户手动改名后，任何自动命名和项目创建不得覆盖。
9. 顶栏、侧栏与浏览器标题从同一会话标题读取，在同一次状态更新后同步；刷新、切换会话后保持一致。
10. 旧数据只为仍为默认标题且已有消息的会话补名；保留其他历史名称，不猜测其是否为用户手动填写。历史会话名与项目名的旧关联不再延续。

实现上需在耗时理解或计算开始前保存本轮消息及初始题名，并让界面能够呈现该状态；不能继续把首次命名完全放在整轮结束的提交里。该调整需保持请求幂等，重试不能重复创建消息或标题记录。

标题必须作为纯文本渲染。名称含 `#`、`[]`、`< >`、换行或表情时，不得成为 Markdown 标题、链接或 HTML，也不得破坏布局。

### 5.3 顶部布局与裁切排查

对话标题采用 20px／28px、字重 600；辅助信息采用 13px／20px。左右操作使用独立固定空间，标题不被“查看参数”挤出可用宽度。宽度不足时主标题先省略、次要操作进入菜单。

实现时按以下顺序查明截图裁切原因：

1. 检查 Streamlit 自带顶栏是否覆盖自定义内容，明确保留或隐藏策略；不得出现两套高度互相抵消。
2. 检查标题及所有祖先容器的 `overflow`、高度、上边距、字体行高、定位和变换。
3. 检查首次载入、重运行、滚动恢复和缩放是否导致标题进入顶栏下方。
4. 给标题建立独立内容区域与明确的顶部安全距离；粘性顶栏要预留实际高度。
5. 在 100%、125%、150%、200% 缩放下比较截图；标题字形上下均完整，不能只验证默认缩放。

不得仅把全页 `padding-top` 加大作为最终修复，这可能掩盖遮挡问题并让首页留白失衡。

## 6. 液态玻璃视觉规范

### 6.1 材质分层

| 层 | 用途 | 视觉规格 |
|---|---|---|
| L0 背景 | 整个应用 | `#EEF2F6`，局部低对比蓝灰光晕；不使用动态壁纸 |
| L1 内容 | 消息、计算表格、参数字段 | `#FAFCFE` 或高不透明近白底；文字和数据自身不模糊 |
| L2 玻璃操作面 | 侧栏、顶栏、输入容器 | 白色约 72%–82% 不透明度；背景模糊 18–24px，轻饱和 115%–125% |
| L3 浮层 | 菜单、轻提示、详情外壳 | 白色约 88%–94%；模糊约 24px；内部表单与长文字保持实底 |

L2 的推荐初始值：白色 78% 填充、22px 背景模糊、120% 饱和；1px 淡白上缘高光；轻微冷灰外轮廓；阴影可从 `0 8px 28px rgba(31,50,73,.08)` 起调。它们是打样参数，需在真实背景和浏览器中验证后定版。

光线方向统一为左上。高光只覆盖容器边缘，不覆盖文字。背景只允许有限的透色变化；高频操作区避免叠加多层模糊。拖动、选择文字、表格滚动不加入折射变形。

### 6.2 颜色与状态

| 语义 | 建议颜色 | 使用范围 |
|---|---|---|
| 主文字 | `#172334` | 标题、正文、重要数据 |
| 次要文字 | `#526173` | 项目归属、辅助说明 |
| 弱提示 | `#64748B` | 时间与非关键提示；仍需检查对比度 |
| 主强调色 | `#245FC7` | 当前项、主按钮、链接、焦点 |
| 选中底色 | `#E8F0FD` | 当前对话、方案选项 |
| 待处理 | `#8A5200` + `#FFF3D8` | 缺参数、历史结果、待确认 |
| 错误／危险 | `#B42332` + `#FDECEF` | 导入失败、删除、无效输入 |
| 操作成功 | `#206A55` + `#E8F5EF` | 保存、导入完成；不表示工程合规 |

状态必须同时有文字或图标，不能只靠红绿。金额减少不能自动配“通过”“安全”或“方案更优”；使用“减少／增加”与正负号表述。

本次对上述主要文字与实色底进行了色值计算，正文、次要文字、弱提示、主按钮白字及三类状态文字的对比度均大于 4.5:1；其中弱提示约 4.63:1，余量较小。该结果只适用于表中实色搭配，透明合成后的对比度、图标边界和焦点仍需实施时实测，必要时加深弱提示或提高底色不透明度。

### 6.3 字体、空间与圆角

- 中文优先系统字体：Windows 使用 Microsoft YaHei，Apple 平台使用 PingFang SC；西文使用系统无衬线回退。避免为视觉差异引入中文大体积网络字体。
- 正文 16px／26px；辅助 13px／20px；表格 14px／22px；顶栏 20px／28px；首页标题 28px／38px；结果主数字 28px／34px。
- 数字启用等宽数字，单位独立、对齐；精度沿用现有计算与报告规则，不在界面自行改变有效数字。
- 间距基准为 4、8、12、16、24、32px；消息组间距 24px，段落间距 10–12px。
- 外层玻璃面圆角 20px；输入框 20–24px；结果卡 16px；按钮 10px；小状态标签 6px。
- 阴影表达层级，不给每条消息、每个字段、每个标签都加阴影。

### 6.4 动效与可访问性

- 悬停、按下、焦点反馈 120–180ms；菜单或详情出现 180–240ms，位移约 4–8px。
- 不给聊天长文本做逐字淡入，不做持续漂浮、光标追随或大幅弹跳。
- 首轮可仅对透明度、位移做过渡；模糊半径保持稳定，避免对整屏持续重绘。
- 普通文字对比度目标至少 4.5:1，大文字至少 3:1；交互边界与焦点至少 3:1。玻璃表面必须按实际合成背景测量，不能只检查色值表。
- 识别减少动态效果偏好；同时在外观设置提供“降低透明度”。不支持背景模糊、设备性能不足或启用降低透明度时改为实色，布局不变。
- Tab 可到达全部控件；Enter/Space 激活；Escape 关闭非破坏性菜单与详情；关闭后焦点回到触发控件。确认弹窗管理焦点，不能落到背后的页面。

## 7. 核心界面与交互修改

### 7.1 空白首页

首页只有产品名、一句能力说明、输入区和三项轻量入口，保持“可以马上开始”的感觉。

推荐文案：“描述幕墙尺寸和材料，我会整理参数、计算理论用量，并比较材料金额。”

三项入口调整为：

- **录入方案**：打开空白参数表；关闭且未保存不创建项目。
- **调整并比较**：已有原方案则显示当前基准并聚焦输入；无原方案则提示“先描述原方案”，不制造虚假两方案卡。
- **查阅资料**：显示当前可检索资料数量；无资料则提供上传入口，保留用户问题。

点击任务入口后以轻提示条标明任务，允许退出，不增加永久“聊天模式”限制。用户下一句话的真实意图优先，不把会话锁死在首页选择中。

范围说明默认一行，详细范围可展开。旧数据迁移提示保留为独立通知，与正常任务入口区分。

### 7.2 对话区

用户消息右侧对齐，浅蓝灰气泡，最大约正文宽度 82%；长表格和文件预览可占整行。助手消息左侧，以清晰正文为主，保留一个尺寸适中的品牌／角色标识。

头像建议 28–32px，不使用截图中容易占据视觉注意力的大边框头像框。助手内容按“直接回应 → 结果／依据 → 下一步”排列。处理状态放在本轮回复附近，完成后被正式内容替换。

默认不在每条正常消息下重复显示模型名、耗时和内部信息；连接降级会影响使用时才提示“在线理解暂不可用，可继续填写参数”，详细原因进入设置。

多项动作按主次排列，当前最有价值的动作仅一个主按钮，其余为次按钮或文字操作。动作超过三项时把低频项收入更多菜单。

### 7.3 输入区与处理中状态

输入容器是主要玻璃组件。内部包括附件队列、文本区、底部工具行。

- 文本区起始约 2 行，最高约 6 行；超出内部滚动。
- 中文输入法组合阶段 Enter 不发送；普通 Enter 发送，Shift+Enter 换行，并提供简短说明。
- 没有文本和附件时发送按钮禁用；有合法输入时高亮；请求处理中显示状态并防止同一请求重复提交。
- 附件可在提交前移除，每份显示文件名、类型及用途：“参数表导入”或“资料查阅”。
- 上传格式与能力提示放在附件入口附近；空白模板从输入区可直接下载，不再藏在维护页。
- 错误保留输入和附件；“重试”重用本次请求上下文，避免重复写入相同消息或导入记录。
- 当前无可靠取消能力时使用“正在处理，可等待本轮完成”。不得显示点击后没有取消效果的停止按钮。取消能力需单独接入并验证后再出现。

P2 滚动增强：用户已在底部时跟随新结果；向上阅读时保持位置，显示“有新结果”按钮。请求进行中切换会话不能把结果写到新会话。

### 7.4 参数确认与修改

首次计算确认卡展示本次实际输入、任务范围、计量口径与主要缺项，按钮命名“确认参数并计算”。不使用会被理解为工程审查的“审核通过”。

参数详情按“尺寸与分格／立柱／横梁／报价口径”分组，单位贴近输入值。表单明确原方案与调整方案；沿用项显示“沿用原方案”，手动修改后显示“已调整”。

保存动作改为“保存参数”，有变更时可额外提供“保存并计算”；二者含义分明。对比当前值与编辑值，展示主要变化，例如“分格宽：1.2m → 1.5m”。空值含义沿用现有明确规则，不能悄悄把清空解释成继承。

关闭未保存表单时提示保留／放弃编辑；没有改动时直接关闭。参数保存后顶部状态更新为“参数已修改，结果待更新”；历史结果卡保持原数值。

P1 在 Streamlit 中可先保留经过整理的模态表单；右侧抽屉列为增强，不假设原生组件已经提供稳定抽屉能力。核查规则移动到“项目高级设置”，名称改为“演示规则”；不在基础参数编辑中形成主要标签页。

### 7.5 结果卡

结果卡使用近白底、明确标题与少量玻璃外层，不直接把数字浮在变化背景上。

由上到下固定四层：

1. **结果身份**：本次计算／部分结果／历史结果；原方案与调整方案版本；时间。
2. **核心摘要**：本任务最重要指标及变化。例如“材料金额减少 1,215.00 元（12.45%）”。只有金额已计算、两方案可比时才出现该摘要。
3. **指标表**：原方案、调整方案、差值；差值统一“调整−原方案”。缺值明确写“缺单价，未计算”，不显示 0 或含糊短横线。
4. **状态与操作**：数据来源／复核状态、计量范围一行、查看依据、下载比选表、技术追溯包。

优先展示用户请求的指标：问用量优先长度／质量，问金额优先金额，问差异优先变化，不固定把金额放在所有任务之首。

表格数字右对齐、列头单位清楚、零值与缺失不同；长说明进入展开内容。无可比金额时仍可展示可算指标，并明确未覆盖部分。

历史卡上方固定琥珀色提示：“参数已修改 · 此卡为历史结果”，并给“按当前参数重新计算”；历史卡下载文案为“下载此历史版本”，不能伪装成当前报告。下载范围与版本仍写入导出内容。

### 7.6 资料查阅与截图中的答非所问

“查规范里有什么要求”和“验算我的方案是否安全”是不同任务。截图中的提问更接近资料查询，但当前回答直接转成结构验算限制，缺少对查询的承接。

源码可确认：范围提示分支先于查询分支；本地查询表达匹配也未覆盖所有“……要求”句式。但本次无法确认截图使用的是在线理解还是本地解析，不能断言某一条正则是唯一根因。

设计要求：

- 资料存在且可检索：返回相关片段、文件名、位置与资料状态；不把片段变成项目合规结论。
- 无资料：保留查询，显示“可以帮你查找立柱截面厚度相关要求，请先上传 PDF、TXT 或 MD 资料”，提供“上传资料”。
- 语义含糊：一次轻量澄清“你希望查阅资料中的条文，还是判断某个截面是否满足要求？”，同时给“查阅资料”“整理待验算参数”两个明确动作。
- 明确要求安全验算：说明当前能力边界，并给可执行后续动作，不重复大段无关能力介绍。
- 不识别、误识别时提供“这是资料查询”纠正操作；纠正后回到原问题，而不是要求重新输入。

资料片段默认展示文件名、可核对的位置和 2–4 行内容，展开看全文片段。PDF 显示文件页序；TXT/MD 显示段落／分段位置，不能一律称为原文页码。没有定位能力的“打开原文”不显示为可点击按钮。

### 7.7 导入、资料库和材料库

上传与导入状态统一为：“待发送 → 处理中 → 待确认／已入库 → 已导入／失败”。资料入库和参数导入使用不同终态文字。

表格导入预览显示文件与工作表、识别成功项、需处理项、写入项目、目标方案、来源性质和预计覆盖字段。确认前明显提示“尚未写入”。对已有参数的覆盖用前后值对比；确认按钮明确为“导入到原方案”等。

多工作表限制在选择处说明：“本次导入一个工作表；其他表需另行导入。”多附件应逐项确认与显示结果，不能用一句“已处理”代替所有文件状态。

资料库显示文件类型、可检索状态、页／分段数量、上传时间、来源审核状态；没有可用文本时显示“未提取到足够文本，需核对文件”，避免把所有情况都错误判断为扫描件。

材料库清楚显示线重、报价单位、税费口径及来源。选择材料时先指定原／调整方案，回显将复制的数据；注明“复制到当前项目”，避免暗示跨项目实时联动。

### 7.8 设置、删除与错误

设置重组为“外观与阅读／模型连接／工作区管理／高级维护”。回收站在工作区管理内有明确入口，模板下载不再依赖维护入口。共享资料与个人材料单独管理。

危险操作区别于普通保存。删除前列出被操作对象、名称和影响；软删除后反馈“已移入回收站”，提供前往回收站。永久删除和清空沿用必要的明确确认，不把外部下载文件计入应用删除范围。

错误结构为“发生了什么 + 已保留什么 + 可以怎么做”。例如：“表格暂未导入，当前方案没有变化。请选择‘尺寸’对应的参数后再试。”日志和异常栈进入技术详情，主界面不展示长错误文本。

## 8. 状态体系

| 状态 | 展示位置 | 用户能做什么 |
|---|---|---|
| 空白 | 首页 | 描述方案、录入参数、上传资料 |
| 理解／处理消息 | 当前轮回复位置与发送按钮 | 等待；不重复提交同一请求 |
| 待补参数 | 助手问题及参数摘要 | 补充、跳过、先算可算部分 |
| 待首次确认 | 参数确认卡 | 确认并计算、修改参数 |
| 部分结果 | 结果卡顶部 | 查看已算内容、补缺项 |
| 当前结果 | 结果卡顶部 | 调整、查看依据、导出 |
| 历史结果 | 旧卡顶部与导出入口 | 查看历史、按当前参数重算 |
| 在线理解降级 | 当前轮简短提示 | 本地解析、填写表单；查看连接详情 |
| 文件失败 | 对应附件／导入卡 | 重试、替换文件、查看原因 |
| 无查询结果 | 查询卡 | 换关键词、补充资料；不推断没有要求 |

不同状态不能仅用颜色表达；旧卡、部分卡、当前卡可同时存在，各自携带状态。全局状态不能把所有历史消息改成同一个结果状态。

## 9. 技术落地与工作包

本轮优先沿用 Python／Streamlit 与现有计算内核。名称与状态问题不需要迁移框架；先建立样式变量和稳定组件边界。不得用一组依赖临时 DOM 层级的 CSS 假装完成所有目标。

| 工作包 | 内容 | 主要位置 | 验收出口 |
|---|---|---|---|
| W01 P0 | 会话标题独立、首次消息命名、手动锁定、旧数据补名 | `agent/assistant.py`、`storage/workspace.py`、`ui/chat.py` | 无项目问答也有正确标题；改名不改项目 |
| W02 P0 | 标题区与侧栏行重做、选中态、图标对齐 | `ui/chat.py`、`ui/style.py`、`app.py` | 标题完整、行内不挤压、不误触 |
| W03 P0 | 资料查询与安全判断交互回归；历史结果定位 | `agent/parser.py`、`agent/extraction.py`、`agent/assistant.py`、结果渲染 | 截图问题有恰当承接；结果版本清楚 |
| W04 P1 | 色彩、字体、尺寸、材质、焦点、降级主题 | `ui/style.py` 及主题配置 | 全界面材质一致，内容对比度合格 |
| W05 P1 | 首页、消息、输入状态、结果卡与操作层级 | `ui/chat.py`；按组件拆分 UI 模块 | 完成主流程，缺项与失败不混淆 |
| W06 P1 | 资料／材料入口、参数表单、导入预览、设置重组 | UI 模块与现有服务接口 | 高频操作可达，保存目标明确 |
| W07 P1 | 视觉、键盘、缩放、标题状态和数据隔离验收 | 对应测试与人工检查记录 | 本文验收表通过，留存截图 |
| W08 P2 | 精细滚动、新结果提示、可靠抽屉、可取消请求 | 自定义前端组件／任务执行接口 | 每项能力独立验收后启用 |

`ui/chat.py` 目前集中了大量界面职责。实施时可按侧栏、顶栏、消息、结果卡、详情和设置拆分，保持只调用现有业务服务，不把计算公式移入界面。

技术边界：

- 避免全局 `[class*="css"]` 或无差别字体覆盖；图标字体与业务文字分别处理。
- 不用分别输出的 HTML 开关标签跨越原生组件来构造父容器；需使用框架稳定容器或受控组件。
- 侧栏标题省略、选中态、固定菜单位若无法通过原生组件可靠实现，可封装最小自定义组件，并保留语义与键盘操作。
- 浮层不放进会裁切它的历史滚动容器；建立统一层级：内容、粘性操作栏、菜单、模态框、提示。避免随手设置极大层级数值。
- 未建立真实异步请求接口前，不实现视觉上可取消但仍后台写入的假取消。
- 高透明效果不适用于导出和打印；报表使用实色、高对比，不带背景模糊。

实施顺序：W01–W03 → W04 → W05–W06 → W07；W08 按稳定性单独安排。名称、遮挡和误操作仍未解决时，不以玻璃效果完成作为交付依据。

性能目标建议：不含服务端处理的本地悬停、聚焦、菜单等反馈在约 100ms 内开始；滚动和输入无持续明显卡顿。以明确记录的演示设备实测，不能用机器无关的“60fps”口号代替测量。若材质影响输入与滚动，优先降低模糊层数和范围。

W08 启用时追加验收：历史阅读不被强拉到底部；新结果提示跳转准确；取消请求确实停止或明确标为已取消，并阻止迟到结果误写；运行中切换会话不串结果。

## 11. 设计与开发交付清单

视觉打样至少覆盖：空白首页、普通无项目问答、参数待补、首次确认、单方案结果、两方案比较、历史结果、资料查询、表格导入、参数详情、资料库、设置与窄屏。

开发交付包括：标题与状态逻辑、统一视觉变量、可访问的侧栏行与操作控件、核心页面、降低透明度回退、必要回归测试及验收截图。最终验收使用用户实际问题和隔离的人工录入数据，不预装演示业务数据。
