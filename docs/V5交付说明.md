# 幕墙方案助手 V5：AI 解读与方案决策辅助 · 2026-10-15

修改基线：`发布/幕墙方案助手_V4_UI修订_20261015`（已核对：其源码压缩包中的业务代码与完整程序 `幕墙方案助手/_internal/app` 逐文件一致，只是压缩包不含 `resources`、完整程序不含 `tests`）。V4 发布目录未做任何改动；本目录是新的独立交付。

## 一、现在能做什么

**1. 规范问答：AI 解读**
- “规范问答”默认是“AI 解读”。已在设置中配置模型、且你没有主动关闭时，提问会**实际调用该模型**；回答下方写明“实际调用 · 模型名称 · 用时”。
- 模型会阅读本次检索到的相关条文，以及相邻条文、适用范围、术语定义和被引用的条文（不是整份 PDF），然后用自己的话回答：先直接回答，再分成“规范明确要求 / 适用条件、限制与例外 / 基于资料和项目条件的分析 / 一般工程建议 / 尚缺条件、暂不能确定”，并提出需要你补充的条件。
- 正文中的 [1][2] 对应下方“备注 · 依据出处”：标准编号、版本、条款、**原 PDF 文件页**与印刷页码候选、国家/行业/地方标准、是否强制性条文、现行状态。这些由程序按登记信息生成，模型不能编写。强制性条文只认资料公告页的明确文字；识别不到就写“待核实”；现行状态一律“待核实”。每条出处都可以展开完整原文，并打开原 PDF 原页。
- 可以选择“结合项目条件”，用已有项目的参数来解读（只读取，不改项目）。
- 想只看原文，可以选“查找原文”；不想调用模型，可以取消“AI 解读使用已配置模型”，这个选择会被记住。

**2. 修改方案：先理解，再追问**
- 说“把分格加大”“减少立柱”“立柱换一种型材”等没有给数值的话，程序会说明它理解成什么、对应哪个参数、当前值是多少，追问关键数值，并列出对成本、构造、施工、维护、规范核查的可能影响。**在你给出数值之前，方案参数不变，也不会补任何数值。**
- 说“加大”却给了更小的数值时，会提醒你核对。
- 说“我更看重外观通透”等，会记录为决策目标，之后的分析按这个目标给倾向。

**3. 重新计算后自动给出方案分析**（不用再问“为什么”）
- 本次改了什么；程序算出的立柱数、长度、质量、材料金额等的变化；
- 原方案、修改方案各自在什么条件下更合适、优势和代价；
- 按你说过的目标，目前更倾向哪个，以及成立条件；没说目标时，分别说明成本优先、外观优先、施工维护下怎么选；
- 进一步决策还需要补充的参数、验算和资料。
- 同时改了几何和材料/单价时，会说明金额差是合计影响，不拆分各因素的贡献。

**4. 变更后的规范核查（逐项）**
- 按变更内容列出可能涉及的核查项（玻璃面板、立柱、横梁、型材壁厚、立柱连接、分格与加工运输），检索相关条文，列出所需参数，并分别给原方案和修改方案一个结果：已核查符合 / 已核查不符合 / 存在潜在冲突 / 暂时无法判断 / 不适用。
- 只有经审核、效力已确认的可机判规则才会给“符合/不符合”；内置 PDF 库是检索资料，不是判定规则库。模型提出的规则只作“待工程师审核的草稿”，不参与判定。

**5. 历史可追溯**：每份分析绑定当次计算的运行编号、两个方案的快照和证据版本，之后再改参数也不会被改写，只显示“历史分析”提示；点“重新生成分析”会形成新的一版，旧版保留。导出的比选表和追溯包包含同一份分析。

**6. 看得到实际调用了什么**：设置 → 模型连接 → “最近的模型调用记录”，显示规范解读/方案分析是否调用、哪个模型、用时、是否回退及原因。记录不含 API Key。

## 二、仍然不能判断什么

- 不做承载力、挠度、连接、锚固验算，不判断结构安全；不从几条检查推出工程“整体合规”。问到这些时，会说明边界，并给出相关条文、判断条件和需要补充的参数。
- 材料金额只是立柱、横梁的理论轴线材料金额，不是工程总造价；不凭线重或重量推断承载力。
- 规范资料未经专业复核，标准现行状态都待核实；OCR 中的数字、表格、公式可能有误，回答会标注“请查看原 PDF 页”。
- 程序校验能证明“出处、原文、页码、数字对得上，要求强度和否定没被改写”，**不能证明解释在语义上完全正确**。真实测试中，校验比较严格：每个问题约有 1～3 条合理但改写较多、或模型自行纠正 OCR 数字的结论被移除（正文会说明有几条被移除，原因见“校验说明”），其余内容照常显示。

## 三、是否实际调用了模型

是。验收使用本机已保存的配置：**DeepSeek / deepseek-v4-pro**。规范解读每次约 10～30 秒，方案分析约 25～35 秒。真实回答原文见本目录《修改前后回答样例.md》，原始记录见 `验收记录/online-v5.json`（V4 对照为 `online-v4.json`）。无模型、超时或调用失败时，界面会写明“未调用模型”或“模型超时……已回退”，计算结果和本地规范检索照常可用。

## 四、安装与验证

- **新安装**：运行 `幕墙方案助手_V5_安装包.exe`，不需要管理员权限。打开后点左侧“规范问答”，内置规范库（91 份登记文档）已默认选中，可直接提问。
- **从 V4 升级**：直接运行 V5 安装包覆盖安装即可（同一安装标识）。项目、聊天、自定义资料、资料选择和模型配置都会保留。已经打开的旧程序需先关闭控制窗口。
- **便携运行**：运行 `幕墙方案助手/幕墙方案助手.exe`，需保留整个目录。
- **自己验证一次**：在规范问答里问“隐框玻璃幕墙的硅酮结构密封胶有什么要求？”，应看到“AI 解读 · 实际调用”、分段的解释和 [1][2]，展开出处能打开原 PDF；新建对话录入一个方案并计算，再说“把分格宽改为 1.5m，与原方案比较”，应自动出现方案分析和逐项核查。

## 六、如实说明的未完成项和问题

- **冻结运行时没有重新打包**：沿用 V4 已验证的启动器和 Python 运行时（逐文件一致），只同步了业务代码。本次新增代码只用到运行时中已有的库。
- 一次安装后端到端运行中，方案分析的模型响应过慢，超过了测试脚本 240 秒的等待上限而失败；重跑通过。程序本身的模型超时为 120 秒（连接中断会重试一次），超时后会回退到本地模板分析并注明原因，但最坏情况下用户需要等待较长时间。另有两次失败是测试脚本读取页面过早造成的，已修正脚本后重跑通过。
- 验收过程中，我在结束测试进程时**误关闭了本机上原本在运行的一个幕墙方案助手实例**（占用 8501 端口的那个进程）。它的数据保存在本地数据库中，不会丢失，需要时重新打开即可。
- 未验证：中文输入法实际组合输入、浏览器原生缩放、触摸设备和屏幕阅读器；只测试了 DeepSeek，其他服务商（智谱、Kimi、Claude）沿用原有调用方式，未做在线验证。
- 标准层级按编号规则识别；强制性条文清单来自 OCR 的公告页文字（91 份中识别到 20 份），未经人工核对。
