# 02 数据表结构

版本：v0.2。以下是逻辑结构和数据契约，不含建表语句。推荐本地 SQLite 保存索引与运行记录，不可变 JSON 保存完整快照；小型数组和字段映射可作为 JSON 字段，无需拆成大量物理表。P0 无登录权限表、供应链表或完整工程造价表。

## 1. 通用类型与约束

| 类型／约定 | 定义 |
|---|---|
| ID | 非空字符串；演示 ID 可读，运行和快照 ID 全局唯一 |
| Decimal | 序列化为十进制字符串；输入最多 6 位小数，工具内部至少 28 位有效十进制精度；拒绝 NaN、Infinity、负长度和负质量；不以二进制浮点直接做金额运算 |
| 时间 | ISO 8601 带时区；存储统一 UTC，页面按 Asia/Shanghai 展示；工程核查日期独立于程序运行时间 |
| 引用 | PK 为主键，FK 为外键；引用必须指向明确的数据包／记录版本，不能只指向“最新版” |
| 空值 | null 是缺失，不等于零；显式清空必须另存 binding_state=cleared；缺失和非法值分别记录 |
| 单位 | 长度 m（接受输入 mm/cm/m 并归一）、面积 m²、质量 kg、线重 kg/m、单价 CNY/kg、金额 CNY；第一版不默默换算其他货币或含税价格 |
| 数值边界 | W/H/b/h/floor_height/线重严格大于 0；价格大于等于 0，零价须显式确认；W/b 和 H/h 精确整除；不取整处理边跨 |
| 显示 | ROUND_HALF_UP；长度质量 3 位、金额 2 位、单位面积质量 4 位、百分比 2 位；不从已舍入展示值计算总计和差值 |
| 版本不可变 | 数据包、方案快照、工具输出成功持久化后不可覆盖；草稿是可编辑对象，有递增 revision |

## 2. 共享字段对象

### 2.1 FieldValue：所有业务输入字段的值与来源

| 字段 | 类型／必填 | 含义和约束 |
|---|---|---|
| value | Decimal／文本／布尔／null；必填键 | 归一后的值；缺失为 null |
| unit | 枚举或 null；必填键 | 数值有量纲则必填；ID 或日期无量纲 |
| raw_value、raw_unit | 文本或 null | 保留原始输入；不把无法解析文本直接送入计算 |
| provenance_ids | ID 数组；必填 | 指向来源记录；空字段可关联 unknown 来源记录 |
| binding_state | 枚举；必填 | inherited、modified、cleared、missing；继承必须记录 inherited_from |
| confirmation_status | 枚举；必填 | unconfirmed、confirmed；仅表示本次使用确认，不表示专业审核 |
| inherited_from | 字段引用或 null | 必须可定位到基准快照及字段路径 |
| generation_method | 枚举；必填 | provided、llm_extracted、engineer_adjusted；派生输出另外使用 program_derived |
| issues | 错误对象数组；必填 | 缺单位、非法值、冲突等；由程序产生 |

### 2.2 SchemeParameters：方案参数字段表

下列每个字段都是 FieldValue；表中“必要”是对应运行入口的门槛，不要求所有草稿都完整。

| 字段名 | 值类型／单位 | 必要场景 | 示例 |
|---|---|---|---|
| width_m、height_m | Decimal／m | 长度及以上 | 12、9 |
| grid_width_m、grid_height_m | Decimal／m | 长度及以上；R01/R02 按依赖取值 | 1.2、1.5 |
| floor_height_m | Decimal／m | R03；非材料计算门槛 | 3 |
| reported_area_m2 | Decimal／m²，可空 | 导入时有面积则做一致性检查 | 108；计算面积由工具生成 |
| column_profile_id、beam_profile_id | ID | 质量及以上 | COL-A、BEAM-A；类型必须对应 |
| column_mass_override、beam_mass_override | Decimal／kg/m，可空 | 仅用户显式覆盖材料线重时 | 默认 null；非空时必须有来源和使用确认 |
| price_basis_id | ID，可空 | 成本 | DEMO-PRICE-001 |
| column_price_override、beam_price_override | Decimal／CNY/kg，可空 | 仅用户显式调整价格时 | 不直接改价格库；运行快照保留覆盖原因 |
| measurement_model_id | ID | 长度及以上 | rect_uniform_axis_v1 |
| region、check_date | 文本／日期，可空 | 对应正式证据明确依赖时 | 演示包为空，不默认填运行日期 |

来源线重由规格记录解析。显式覆盖价格继承该基准的货币、未税和费用范围，仅在确认后用于本次方案；如果用户改变口径，必须形成新的价格基准，不用单价覆盖偷换口径。零值确认独立记录在确认凭据中，null 不产生零值确认。

### 2.3 Metric：计算输出

| 字段 | 类型／约束 |
|---|---|
| metric_key | 如 column_length_m、total_cost_cny、panel_area_m2 |
| value、unit | 未舍入 Decimal 字符串及量纲；无法计算时 value=null 并附 reason_code |
| display_value | 根据固定舍入策略生成，不作为后续计算输入 |
| input_refs | 参数、规格、报价或上游 Metric 的确切引用 |
| source_statuses | 来源集合，保留 synthetic/public/verified/pending 的所有实际成员，不强行归为单一等级 |
| contains_synthetic、contains_pending | 按本指标依赖闭包计算；案例中与此指标无关的空地区不得污染其来源集合 |
| generation_method | 计算指标固定 program_derived |
| review_status | 初始 pending_professional_review；演示结果即使经复核也保留 synthetic |
| formula_id、tool_version、step_refs | 精确定位公式和计算步骤 |

## 3. 来源与审核：三种状态分别存

| 字段 | 允许值 | 含义 |
|---|---|---|
| source_status | synthetic、public、verified、pending | 输入来源身份与可用性；verified 表示来源数据经确认，不代表当前工程结论已确认 |
| source_type | team_constructed、public_document、enterprise_record、unknown | 原始来源类型；public 被审核后仍保留 public_document |
| review_status | unreviewed、in_review、pending_professional_review、technically_reviewed、rejected、outdated | 专业审核进度，与来源独立 |
| generation_method | provided、llm_extracted、program_derived、engineer_adjusted | 数据生成方式，与来源及审核独立 |

程序派生结果不自动设置 source_status=verified 或 pending，而使用 Metric.source_statuses 列出原始来源集合。如输入全为 verified，显示“来源：已确认企业数据；生成：程序计算；结果：待专业复核”。存在 synthetic 则突出含演示数据。来源未知的关键数值阻断对应计算；仅尚未专业复核但来源已知的结果可计算并明确标识。

## 4. 主数据逻辑表

每个字段行中的列表字段共享同一类型；没有另列说明的 ID 为非空文本。所有版本内业务值使用来源引用。

### DB01 dataset_versions：数据包版本

| 字段 | 类型／必填 | 键或约束 |
|---|---|---|
| dataset_version_id | ID／是 | PK |
| dataset_id、version、schema_version | 文本／是 | dataset_id+version 唯一；schema_version=0.2 |
| content_hash、file_manifest | 文本、文件项数组／是 | 每项包含路径、内容哈希、数据类型；启用前验证 |
| validation_status | 枚举／是 | staging、valid、invalid；只有 valid 可启用 |
| default_case_id、created_at | ID、时间／是 | 默认案例必须存在 |

当前启用包保存为应用设置中的单一指针；切换指针与验证结果持久化需原子提交，失败保持旧指针。相同 dataset_id+version 不允许不同哈希再次导入。

### DB02 provenance：来源记录

| 字段 | 类型／必填 | 键或约束 |
|---|---|---|
| dataset_version_id、provenance_id | ID／是 | 复合 PK |
| source_status、source_type、review_status、generation_method | 枚举／是 | 见第 3 节；未知来源不自动推断企业来源 |
| source_ref、location | 文本／条件必填 | public/verified 必须有来源定位；synthetic 写团队构造来源 |
| source_hash、captured_at | 文本／时间，可空 | 原始文档存在则记录 |
| reviewer、reviewed_at、review_scope、notes | 文本／时间，可空 | verified 或 technically_reviewed 必填审核人、时间、范围和依据；不能让模型自动填写 |

### DB03 cases：案例

| 字段 | 类型／必填 | 键或约束 |
|---|---|---|
| dataset_version_id、case_id | ID／是 | 复合 PK |
| case_name、curtain_wall_type、design_stage | FieldValue／是 | P0 仅 component_glass、scheme_design |
| required_rule_set_id | ID／是 | FK DB07；空清单须明确说明，不能默默视为已全面核查 |
| default_parameters | SchemeParameters／是 | 初始值；真实运行使用方案快照中的值 |
| baseline_seed_id | ID／是 | 指向导入方案种子；加载后建立方案版本 |

### DB04 profiles：型材

| 字段 | 类型／必填 | 键或约束 |
|---|---|---|
| dataset_version_id、profile_id | ID／是 | 复合 PK |
| profile_name | FieldValue／是 | 演示名称不冒充厂家型号 |
| component_type | 枚举／是 | column 或 beam |
| linear_mass | FieldValue／是 | kg/m、>0；null 可作为缺资料记录但阻断质量模块 |
| applicability_notes | 文本／是 | “未确认工程适用性”等；不是承载力结论 |

### DB05 price_bases 和 DB06 prices：价格基准与明细

| 表／字段 | 类型／必填 | 键或约束 |
|---|---|---|
| DB05：dataset_version_id、price_basis_id | ID／是 | 复合 PK；该包固定唯一 price_basis_version |
| DB05：price_basis_version、name | 文本／是 | 已保存版本不可改 |
| DB05：currency、price_unit、tax_basis、cost_scope | 枚举／是 | CNY、CNY/kg、exclusive、aluminum_material_only |
| DB05：quote_date、valid_until、provenance_id | 日期可空、ID 必填 | 演示无真实报价日期；企业有效期未知则明确提示 |
| DB06：dataset_version_id、price_basis_id、profile_id | ID／是 | 三字段复合 PK，分别 FK DB05 和 DB04；杜绝重复报价 |
| DB06：unit_price | FieldValue／是 | >=0；null 代表缺报价；报价不存在与 null 均阻断相应成本 |

方案通过自己的 dataset_version_id+price_basis_id 定位冻结的报价版本，再分别以 column_profile_id 和 beam_profile_id 读取两个明细。覆盖单价引用原报价及覆盖来源；旧报告一直保留原始解析后的两个报价快照。

### DB07 rule_sets：必查清单

| 字段 | 类型／必填 | 键或约束 |
|---|---|---|
| dataset_version_id、rule_set_id | ID／是 | 复合 PK |
| rule_set_version、name、scope | 文本／是 | 名称必须说明覆盖范围 |
| members | 清单项数组／是 | 每项有 item_id、rule_id、display_order、required=true；同一规则不重复；FK DB08 |
| provenance_id、coverage_notes | ID、文本／是 | 正式清单需要工程审核记录；演示清单含 3 项 |

### DB08 rules：证据和可判定规则

| 字段 | 类型／必填 | 键或约束 |
|---|---|---|
| dataset_version_id、rule_id、rule_version | ID、版本／是 | 包内 rule_id 唯一并固定版本 |
| evidence_type | 枚举／是 | demo_rule、formal_clause、enterprise_rule |
| title、exact_text、source_ref、location、content_hash | 文本／是 | demo_rule 写团队自构造规则文本；正式资料缺原文或来源则不具备判定资格 |
| standard_name、standard_number、edition、clause_number | 文本可空 | demo_rule 必须为空；正式条款资格检查时要求完整 |
| publication_date、effective_from、effective_to | 日期可空 | 不是所有文档都有有效截止日期，不臆造 |
| effect_status、status_checked_at、replaced_by | 枚举、时间可空、引用数组 | current、repealed、replaced、partially_replaced、unknown、not_applicable；演示用 not_applicable |
| applicability | 条件对象／是 | 幕墙类型、阶段、地区条件、日期条件、说明 |
| required_parameters | 字段路径数组／是 | 如 grid_width_m、panel_area_m2、floor_height_m |
| machine_checkable | 布尔／是 | 不可机判直接走人工判断 |
| predicate | 受控条件或 null | lhs_metric、operator、threshold FieldValue；操作符限定 <=、<、>=、>、==；不得执行字符串代码 |
| required_tools | 工具 ID 数组／是 | 派生面积需 TL07；直接字段不依赖几何工具 |
| provenance_id | ID／是 | FK DB02；来源审核、效力审核和规则映射审核独立记录 |
| effect_review、mapping_review | 审核对象／是 | review_status、reviewer、reviewed_at、scope；正式机判前必须满足资格 |

测试替身不能以 formal_clause 身份导入业务库。测试环境仅在隔离的判定层验证真假映射；真实知识库仍为 0 条正式条款。

## 5. 交互、运行与追溯逻辑表

| 表 | 字段及类型 | 键、关联和生命周期 |
|---|---|---|
| DB09 drafts 草稿 | draft_id ID；case_id/dataset_version_id ID；revision 整数；baseline_snapshot_id ID 可空；requested_task 枚举；parameters SchemeParameters；pending_patch 变更数组；active_question_id ID 可空；updated_at 时间 | PK draft_id；编辑须校验 expected_revision；自然语言提取只写 pending_patch；接受变更后 revision+1；null 不继承 |
| DB10 scheme_snapshots 方案快照 | snapshot_id ID；scheme_id ID；version 整数；parent_snapshot_id ID 可空；dataset_version_id/case_id ID；draft_id/revision；parameters；resolved_profiles/resolved_prices 对象；confirmation_record；content_hash；created_at；change_reason | PK snapshot_id；scheme_id+version 唯一；确认后不可变；允许缺价的部分快照；绑定价格、线重和来源，不依赖后续材料表变化 |
| DB11 runs 运行 | run_id ID；request_id ID；requested_task；target_modules 数组；baseline_snapshot_id/candidate_snapshot_id 可空；query_context 可空；input_hash；tool_versions；execution_state；module_statuses；rule_set_snapshot；coverage；started_at/ended_at；issues | PK run_id；request_id 唯一；相同 request_id 不同输入拒绝；不同 request_id 的显式复算创建新 run；查询任务允许无方案快照 |
| DB12 questions 追问 | question_id ID；draft_id/revision；field_path；reason_code；question_text；expected_type/unit；priority；status；answer；created_at/resolved_at | PK question_id；同一草稿最多一条 awaiting_answer；答案绑定提问时 revision，过时答案先提示再应用 |
| DB13 rule_results 核查结果 | run_id/snapshot_id/item_id；rule_id/version；status；execution_status；actual_values；evidence_ref；reason_code；input_refs；review_items | PK run_id+snapshot_id+item_id；必查项数量与清单匹配；status 九选一或 null（仅执行失败）；execution_status=error 时不能算已判定 |
| DB14 calculation_results 计算结果 | result_id ID；run_id；module；snapshot_ids；metrics 映射；steps 数组；input_hash；tool_version；created_at | PK result_id；指标使用 Metric；steps 含 step_id、formula_id、操作数引用、输出、单位；上游数据的哈希必须一致 |
| DB15 events 事件与工具记录 | event_id ID；run_id/draft_id 可空；request_id；event_type；from_state/to_state；tool_id/version；input_refs；output_ref；duration_ms；error；created_at | 追加写；不保存模型内部推理；不保存密钥；模型记录保存可审计提取草案、模式和确认差异 |
| DB16 exports 导出 | export_id ID；run_id；request_id；completeness；artifact_manifest；input_hash；created_at | 输出 Markdown、CSV、JSON、清单及哈希；只取指定 run，不读取当前可变草稿；重复 request_id 返回同一导出 |
| DB17 review_records 专业复核，P1 | review_id ID；target_type/target_id；reviewer；scope；opinion；review_status；created_at | 追加记录；不能改变来源身份或覆写快照；P0 只读取导入记录 |

查询资料返回存入 events 的 output_ref 指向的不可变检索快照；它是候选证据列表，不伪装成 rule_results。run 中 module_statuses 包含 query、geometry、length、mass、cost、comparison、rule_check、report，值为 not_requested、ready、running、done、blocked、error。

## 6. 数据关系与保存边界

数据包 1:N 案例／型材／价格基准／规则；价格基准 1:N 报价；案例 N:1 必查清单；必查清单 N:M 规则（由 members 明确引用）。案例 1:N 草稿和方案快照；方案快照 1:N 运行；运行 1:N 核查、计算、事件和导出。

快照写入与对应确认事件原子完成。运行不能引用仅存在于界面内的参数。工具成功结果持久化后才将模块设为 done；失败留下 error 及已成功的其他模块。导入新包后原草稿与快照固定旧包，不因 UI 默认数据包切换而变动。

## 8. 导入校验与文件映射

manifest → DB01；provenance → DB02；cases → DB03；profiles → DB04；price_bases/prices → DB05/06；rule_sets/rules → DB07/08；schemes → 方案种子，确认时创建 DB10。单文件 JSON 与目录拆分文件必须解析成同一个逻辑对象。

拒绝启用：不支持 schema_version、重复主键、悬空引用、同键不同报价、非法量纲或负数、伪装成正式依据的 synthetic、规则条件包含代码。允许导入并警告：明确 null 的缺价／缺线重、pending 非关键来源、空正式规范库；相应模块仍按运行门槛阻断。仅不同来源的审核尚未完成，不等于文件结构错误。
