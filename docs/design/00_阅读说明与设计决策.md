## 已锁定的业务范围

只覆盖构件式玻璃幕墙方案阶段、单矩形等距立面和铝合金立柱／横梁的理论轴线用量及材料成本。包含边柱、顶底横梁；不扣柱宽和连接间隙；不计损耗、玻璃、五金、加工、运输、安装、税费。规格适用性必须由工程师确认。

演示数据包全部业务数值和三条演示规则来自团队构造，标为 synthetic；缺失地区和核查日期为 pending。正式规范条款数量为 0。现有目录中的规范文件未在本任务中完成来源、效力及适用性审核，不自动纳入正式知识库。

## 详细设计中的明确决策

以下属于本包为消除开发歧义作出的设计决定，不是新增工程事实：

| 编号 | 决策 | 对原方案的细化 |
|---|---|---|
| D01 | “规范查询”和“对方案执行辅助核查”是同一页面中的两个操作 | 查询只需问题和必要检索条件；执行核查才检查规则输入，不要求价格或规格 |
| D02 | 先确认所选模块的输入快照，再执行该模块及其前置计算 | 板块面积由几何工具提供；规范文本查询不强制先生成整幅立面几何 |
| D03 | 核查和材料计算在基础几何后分支执行 | 必查项必须有结果状态；核查缺参或无依据不能阻塞独立可用的数量成本 |
| D04 | 报价键绑定数据包中的价格基准版本 | 每个基准版本内 `(price_basis_id, profile_id)` 唯一；版本冻结避免同 ID 对应多份报价 |
| D05 | 派生结果保留输入来源集合，而非用一个 pending 覆盖全部来源 | 来源状态、数据生成方式、专业复核状态独立；结果显示“程序计算／待专业复核” |
| D06 | 参数确认是本次使用确认，不是专业复核 | 保存快照可以包含缺项；缺项阻断对应模块，不能静默回填或默认零 |
| D07 | 正式条款分支用隔离的规则引擎测试替身验证 | 替身不进入业务知识库、不增加正式覆盖数、不编造规范原文；还要验证生产入口拒绝不合格证据 |
| D08 | P0 本地单用户，逻辑数据可由 SQLite 与不可变 JSON 快照承载 | 不要求网络服务或向量库；工具是内部契约，后续可以封装成服务 |

发生术语差异时，业务范围仍以已确认产品方案为准；本包给出了开发所需的字段和状态细化。输入、规则、工具及输出均按版本追溯，不通过“全部通过”表达工程安全或完整合规。
