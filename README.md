# 幕墙方案助手 V5：AI 解读与方案决策辅助（基于 V4 内置规范库）

安装后打开程序，点击左栏“规范问答”，默认选中“内置幕墙规范库”，可直接输入 `JGJ102-2003 5.5.4` 或 `立柱与主体结构连接`。展开引用并点击“查看原始PDF第…页”，即可查看原件图像、切换PDF物理页或下载完整原件。无需建立工程项目、填写资料路径、导入成果或重建索引。

本地检索及原页查看不需要网络或模型密钥。问答方式分“查找原文”和“AI 解读”。已在设置中配置模型且没有主动关闭时，AI 解读会直接调用该模型：发送问题、可选的项目条件和本次检索到的相关条文片段（含相邻条文、适用范围、术语定义和被引用条文），不发送整份 PDF。模型用自己的话总结、解释条件与例外并给出建议；程序按结论逐条校验来源、原文定位、数字单位、要求强度、否定和前提例外，未通过的那一条从正文移除，其余照常显示。出处由程序按登记信息生成。主动关闭模型的选择会被记住；无模型或调用失败时显示本地摘录并说明原因。

## V5 新增

- **AI 解读**：正文分“规范明确要求 / 适用条件、限制与例外 / 基于资料和项目条件的分析 / 一般工程建议 / 尚缺条件、暂不能确定”，用 [n] 引用号关联备注中的出处与原 PDF 入口。强制性条文只认资料公告页的明确文字；标准层级按编号识别；现行状态一律“待核实”。
- **方案修改理解**：“把分格加大”“减少立柱”“换一种型材”等没有给数值的修改，会先说明理解、追问关键数值和可能影响，不改动已生效参数，不补造数值。
- **计算后自动分析**：两个方案成功比较后自动生成分析：本次改了什么、程序计算的变化、两个方案各自更合适的条件与代价、按用户目标的倾向及成立条件、还需补充的参数和验算。数值全部由程序计算；逐句校验，只移除有问题的句子。
- **变更核查**：变更内容 → 可能涉及的核查项 → 相关依据 → 所需参数 → 原方案与修改方案的逐项结果（已核查符合 / 已核查不符合 / 存在潜在冲突 / 暂时无法判断 / 不适用）。只有经审核、效力确认的可机判规则能给出“符合/不符合”；模型提出的规则只作待审核草稿。
- **版本绑定**：每份分析绑定运行编号、两个方案快照和证据版本，保存后不再修改；“重新生成分析”形成新版本，旧版本保留。导出的比选表和追溯包包含同一份分析。
- **调用记录**：设置 → 模型连接中可查看最近的模型调用（是否实际调用、模型、耗时、回退原因），记录不含 API Key。

## 安装与数据

- 使用 `幕墙方案助手_V4_安装包.exe` 安装，默认安装到当前用户的应用目录，不要求管理员权限。支持中文、空格及非 D 盘安装目录。
- 程序与只读规范资源随安装交付。首次打开界面显示校验、部署进度，将预建数据库和索引部署到 `%LOCALAPPDATA%\MqHelper\workspace\standards`；原PDF保留在安装资源内，按登记哈希读取。
- 首次校验时间取决于磁盘，本机测试约10秒。不会重做OCR或解析整库。后续新进程会校验资源完整性，已有数据库不重复导入或重建。
- 项目、聊天、普通文件库及应用设置与规范资源分开。普通“清空工作区”保留规范库；管理页中的“停用内置规范库”仅移除当前用户内置登记和索引，安装原件保留，可恢复。卸载程序保留用户数据。
- 用户主动选择的资料集会保存，包括主动取消全部选择。临时停用资料不会抹掉已保存选择。

## 更新与恢复

普通用户安装新的完整发布包即可更新程序和内置规范库（V5 安装包与 V4 使用同一安装标识，可直接覆盖升级）。启动会按包内容版本自动校验并部署，只替换固定的内置资料集，保留项目、聊天、自行导入资料和设置。部署中断后重启自动重试；半成品不提供检索。

“规范问答 → 管理规范库 → 内置规范库维护与恢复”提供校验恢复和停用。若安装文件丢失或损坏，使用完整安装包覆盖安装后再恢复；不会要求用户手动复制数据库。该恢复使用安装包的可信资源，不能凭空修复已经损坏的唯一原件。

自有规范资料可在管理页“高级：增加或更新自己的规范资料”导入。输入原件和OCR成果目录，只读取清单、逐页文本、映射和必要质量记录；普通文件库上传不等同于规范库导入。已有空库会话在资料就绪后自动选择可用资料；主动选择为空的会话保持用户选择。

## 源码运行与发布维护

源码目录旁的 `resources/standards` 是完整规范包。安装依赖后执行 `python -m streamlit run app.py`。默认用户数据仍在应用数据目录，可用 `MW_RUNTIME_DIR` 指定隔离工作区，`MW_STANDARD_BUNDLE` 指定测试资源包。

发布维护者先用已有导入流程更新审核记录/文本和规范数据库，再使用 `tools/build_standard_bundle.py --library <library.db> --source-root <原件目录> --package-root <成果目录> --output <新包目录>` 生成新版本。工具核对旧登记依赖、使用SQLite备份读取完整快照、只复制确实依赖的资源、去除开发路径、重新生成发布索引并按SHA-256生成清单。不要直接改安装资源或手工修改数据库路径。

Windows构建脚本、依赖锁定及安装器脚本随交付源码归档提供。发布不包含用户项目、聊天、密钥、模型配置或开发工作区。测试见交付目录的《交付与验收记录.md》及JSON原始记录。
